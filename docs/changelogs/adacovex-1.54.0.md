# adacovex 1.54.0

Date: _2026-09-28_

Version bumped 1.53.0 -> 1.54.0.

## Changes

### C1: Site transparency page

New page `docs/site-transparency.md`, linked from the manual index, the
documentation table in `README.md`, `docs/CREDITS.md`, and
`docs/THIRD_PARTY_NOTICES.md`. The page states the full position in one place:

- The build adds no analytics tag, no tracker, and no consent banner, and the
  generated pages load no resource from another domain.
- The sidebar search box runs in the reader's browser, because the search index
  is a static file that the build writes. A search word never reaches a server.
- The hosting provider counts page views in aggregate with its own analytics,
  uses no cookie for the count, obeys Do Not Track, and deletes its web server
  logs after 10 days. The project cannot switch that counting off, and the page
  says so.
- Paid advertising and the flyout menu are disabled for the project through the
  provider dashboard. The page names both dashboard paths so any reader or
  maintainer can check the claim, and it records the one limit: the provider
  still serves free community advertisements that the dashboard cannot remove.
- `adacovex --serve` binds to `127.0.0.1`, so no other machine can reach the
  dashboard. It keeps the theme choice in `localStorage` under the key
  `adacovex-theme`, sets no cookie, writes no log file, and sends nothing to a
  third party.

`docs/conf.py` carries a comment block that ties the build to the page, so the
manual cannot drift from the promise. `docs/contributing/ste100/web-terms.md`
is a new lexicon page with nine Technical Names for the web-site vocabulary, and
the STE100 index and toctree list it.

### C2: User guide landing page

New page `docs/usage/index.md` gives the user guide one landing page, grouped by
task rather than by feature: install and run, assess a project, read the
results, publish in CI, and manage the toolchain. Every entry gives a one-line
description and links to the deeper pages, so a reader can find the CLI flags,
the dashboard, the SBOM, or the standards from one page. The manual index, the
Getting started toctree, and the documentation table in `README.md` now point at
it.

### C3: Search language pinned and no-tracking rule recorded

`docs/conf.py` sets `html_search_language` to `en`, which pins the stemmer to
English instead of letting it follow `language`. A future change to `language`
therefore cannot quietly break the matching of English words. Sphinx builds
search into the HTML builder, so the search box needs no extension and no extra
dependency, and `requirements.txt` is unchanged. The same file now states the
no-tracking rule for both consumers of the build, the online manual and the
offline manual that `--serve` embeds.

### C4: Bundled offline manual regenerated

`src/adacovex-docs_template.ads` is regenerated by `tools/gen-docs.py`, so the
offline manual at `/docs` carries the new transparency page, the new usage
landing page, the new web-site lexicon, and the updated index. The gate
`tools/gen-docs.py --check` passes, and `tools/check-book-links.py` confirms
every link in the bundled manual still resolves. `Adacovex.Docs_Template`
carries `SPARK_Mode => Off`, so the regeneration changes no proof surface.

### C5: README and manual index held to the line cap

`README.md` and `docs/index.md` are back under the 250-line cap of
`tools/check-docs.py`, with no link removed from either page. The trims remove
prose that the documentation table or the target index already carries: the
duplicate dashboard pointer, the `examples` pointer below a complete example
block, the per-lexicon enumeration that the STE100 index page already lists, and
the per-sub-page performance list that the performance index page already
holds. The new transparency row, the new usage-guide row, and the statement
about the site all stay.

### C6: Transparency page gains a See also section

The new transparency page ends with a `See also` section that points at the
third-party notices, the credits, and the bundled offline manual. The offline
manual link matters for the reader who wants the same pages with no hosting
provider in the path, and the notices link carries the licences of the toolchain
that builds the site the page describes.
